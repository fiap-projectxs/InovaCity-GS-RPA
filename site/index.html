O que o robô faz

Ponto de entrada: python main.py. Sem intervenção durante a execução.

  1. Leitura do CSV de ocorrências.Se o arquivo não existe: registra o erro, grava um relatório com status próprio e encerra sem exceção.
  2. Validação de texto, coordenadas e data.Se o dado é inválido: a linha vai para a quarentena com o motivo e o robô segue.
  3. Classificação por NLP (TF-IDF e regressão logística), com confiança.Se a confiança é menor que 0,45: o relato vai para a fila de revisão humana.
  4. Duplicidade: mesma categoria, até 150 m de distância e texto parecido.Se já existe chamado igual: não abre outro, aponta o original.
  5. Prioridade por regras com sinais de risco (queda, criança, cadeirante, invasão de água).Sem sinais: a base da categoria decide.
  6. Notificação a um serviço externo simulado, com 3 tentativas e espera crescente.Se o serviço não responde: o item vai para as notificações pendentes e o robô continua.
  7. Relatório da execução, filas em CSV e registro de IDs já tratados.Se rodar de novo: não reprocessa nada (idempotência).

Temas da disciplina

Quatro temas, cada um com função real no fluxo.

HiperautomaçãoRPA, IA, regras e pessoas juntos

Orquestra o fluxo inteiro em pipeline.py: para cada relato, decide o que o robô resolve sozinho e o que escala para uma pessoa.

O problema não se resolve só com RPA nem só com IA: a classificação é incerta e parte dos casos precisa de juízo humano.

Processos, tarefas e BPM/BPMNprocesso desenhado antes do código

O processo está modelado em BPMN (diagrama no relatório) e o código tem uma tarefa por módulo.

Com tantas exceções (arquivo ilegível, dado inválido, baixa confiança, duplicidade, serviço fora do ar), cada saída precisa ter um destino explícito.

RPA com arquivosCSV, JSON, log

Lê o CSV de entrada e grava as filas em CSV, o relatório em JSON, o log e o registro de IDs já tratados.

Os relatos entram e saem como arquivos, porque o protótipo não assume integração com a prefeitura. Arquivo ausente não derruba a execução.

RPA com IA: tarefas inteligentesNLP, regras e similaridade

Classifica por NLP (TF-IDF e regressão logística), valida e prioriza por regras e detecta duplicidade por similaridade (Jaccard e haversine).

IA onde ela agrega, regras onde a decisão precisa ser auditável. Roda sem GPU e sem chave de API.

Dados, ética e ODS

Dados. Todos os dados são sintéticos. O relato não tem nome, telefone nem CPF, e nenhum dado pessoal real chega a qualquer API. O uso de LLM é opcional e fica desligado: sem chave, ou se a chamada falhar, o robô usa o texto original. Chaves só existem como variável de ambiente.

Ética. O robô não decide quando está incerto: relato de baixa confiança vai para uma pessoa. O maior risco é o viés territorial, porque bairros ou grupos que relatam mais seriam atendidos primeiro. Isso pede acompanhar quem está sendo atendido, não só o que foi priorizado.

ODS. ODS 9 (infraestrutura resiliente), ODS 11 (cidades sustentáveis) e ODS 10 (priorizar acessibilidade reduz desigualdade de acesso). A contribuição é potencial: o protótipo não foi testado com moradores reais.

Limites

Dados sintéticos: o desempenho real não foi medido. O serviço de notificação é simulado e não há integração com a prefeitura. O gancho de LLM é um stub não testado. Prioridade por palavras-chave pode falhar com sinônimos e não foi validada com especialistas. Os limiares de duplicidade (150 m e 0,6) não foram calibrados com dados reais.

Executar

Python 3.10 ou mais novo. Só depende de scikit-learn.

pip install -r requirements.txt
python main.py                 # execução completa; saídas em saida/
python avaliar.py              # acurácia no conjunto de teste
python -m unittest tests.test_rpa

Para repetir as demonstrações de falha:

python main.py --entrada nao_existe.csv --saida saida/demo_entrada_ausente
python main.py --saida saida/demo_servico_fora --simular-servico-fora
python main.py                 # 2ª execução mostra a idempotência

Para gerar de novo este site a partir das saídas: python site/build_site.py
